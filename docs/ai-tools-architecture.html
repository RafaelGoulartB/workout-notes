Arquitetura interna • Tool calling

Como a IA consulta os dados do app

O modelo não acessa o SQLite diretamente. Ele recebe schemas selecionados para a pergunta, escolhe uma função, o app executa a leitura local e devolve JSON. A única operação especial prepara uma proposta de rotina — a alteração real só acontece após aprovação humana.

19tools registradas
18leituras locais
1proposta protegida
3rodadas máximas de tools
Regra central: as tools não são endpoints públicos nem chamadas feitas pela IA diretamente ao banco. São funções Dart registradas em AiToolRegistry e orquestradas por AiChatService.

Economia de tokens

Roteamento e encadeamento

A

Primeira rodada

toolNamesForQuery procura termos de domínio no texto. “Sono” expõe ferramentas de sono; “meta” expõe metas; uma conversa casual pode expor zero tools.

Follow-ups curtos como “e esta semana?” reutilizam a última pergunta do usuário para não perder o domínio.

B

Próxima rodada

followUpToolNames expõe somente dependências úteis. Depois de listar treinos, por exemplo, fica disponível apenas o detalhe de treino.

Isso evita reenviar o catálogo inteiro em todas as chamadas ao provider.

Protocolo

Formato de uma tool call

1

A IA solicita

{
  "id": "call_abc123",
  "type": "function",
  "function": {
    "name": "get_exercise_history",
    "arguments": "{\"exercise_id\":\"uuid\",\"limit\":12}"
  }
}
2

O app responde

{
  "role": "tool",
  "tool_call_id": "call_abc123",
  "content": "{\"ok\":true,\"data\":{...}}"
}

Envelope de sucesso

{ "ok": true, "data": { ... } }

Campos nulos são removidos antes do envio ao modelo para economizar tokens.

Envelope de erro

{
  "ok": false,
  "code": "unknown_tool | error | invalid_args | ...",
  "message": "Descrição legível"
}
Exceção protegida

Como uma proposta de rotina funciona

propose_routine_change não edita a rotina. Ela grava um rascunho em ai_routine_proposals. O usuário precisa aprovar o card; só então AiRoutineMutationService.approve aplica a árvore em uma transação SQLite.
1. Intenção explícita“Crie”, “edite”, “adicione” ou “remova” conteúdo de rotina.
→
2. Dados reaisLista exercícios; em edição, lista e detalha a rotina existente.
→
3. PropostaValida IDs, salva snapshot, árvore-alvo e diff com status aguardando aprovação.
4. Card no chatO usuário aprova ou rejeita. Rejeitar não altera nada.
→
5. RevalidaçãoPara edição, compara a rotina atual com o snapshot. Mudanças externas tornam a proposta stale.
→
6. TransaçãoAplica tudo atomicamente e pede à IA apenas um resumo factual, sem tools.
Prompt e limites

Contexto, histórico e custo

C

Contexto automático

AiContextService injeta um JSON compacto em <workout_data>. Ele contém totais, streak e, conforme o modo, disponibilidade dos domínios.

  • minimal: totais e streak.
  • standard: adiciona cobertura recente de dados.
  • full: também anuncia todos os domínios consultáveis.
T

Controle de tokens

O alvo de entrada é aproximadamente 7.000 tokens. O orçamento do histórico diminui conforme crescem prompt, contexto e schemas, com piso de 1.200 e teto de 6.000.

Transcrições antigas de tools são removidas do wire após a resposta final; continuam persistidas para a interface.

P

Paralelismo

Quando a IA pede várias leituras independentes na mesma resposta, o app usa Future.wait. A ordem original é preservada ao montar as mensagens de retorno.

R

Limites de rodadas

São permitidas até três rodadas com tools. Se ainda houver novas chamadas, o app faz uma requisição final sem schemas para forçar uma conclusão textual.
